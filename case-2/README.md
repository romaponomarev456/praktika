# Кейс 2. Восстановление процесса обработки заявок на закупку (Process Discovery)

## Структура папки

- `task.md` — условие задания
- `submission_template.md` — формат сдачи
- `dataset_description.md` — описание журнала событий
- `students.csv` — исходная выгрузка событий (1000 процессов, 6508 событий)
- `process_schema.mmd` — схема процесса, исходник на Mermaid
- `process_schema.svg` — та же схема, отрендеренная в SVG
- `student_transitions.csv` — таблица переходов (`SourceActivity,TargetActivity`)
- `variants.csv` — таблица полных вариантов маршрута (`Variant,Route,NumberOfCases,Share`)
- `report.md` — отчёт по пунктам из `submission_template.md`
- `analysis.py` — воспроизводимый код анализа на pandas (без ML)

## Как воспроизвести

```bash
cd case-2
pip install pandas
python3 analysis.py students.csv
```

Скрипт группирует журнал по `ProcessInstanceId`, сортирует по числовому `EventIndex`, строит цепочки
активностей, считает переходы и полные варианты маршрута, а также проверяет (через `assert` на всём
журнале) гипотезы о правилах ветвления — результат сохраняется в `student_transitions.csv` и
`variants.csv`.

## Краткая суть результата

Процесс начинается всегда с «Регистрации заявки» и заканчивается одним из трёх финалов: «Заявка
выполнена» (91,1%), «Заявка отклонена» (6,3%) или «Заявка отменена» (2,6%). Восстановлено 12 уникальных
переходов и 8 вариантов маршрута, полностью покрывающих журнал. Ключевые находки: на «Согласовании
руководителем» — четыре исхода (accept/return/reject/cancel), цикл доработки (`return` → «Доработка
заявки» → повтор «Первичной проверки» и «Согласования»), и детерминированный порог `Amount ≥ 150 000`
для обязательной вставки «Дополнительного согласования» перед «Исполнением закупки» — порог подтверждён
без единого исключения на всех 911 случаях, дошедших до проверки бюджета. Подробности, обоснования и
примеры `ProcessInstanceId` — в `report.md`.
